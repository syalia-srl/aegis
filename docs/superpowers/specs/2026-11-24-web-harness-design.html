Web AI services as ordinary Aegis sessions

Spawn a research or brainstorming sidekick backed by Gemini, DeepSeek Chat, Qwen Chat or ChatGPT in the person's signed-in Chrome. Work through the existing Aegis transcript while keeping the original web interface available for manual controls.

01Intent and measured evidence

These agents primarily research online, compare alternatives, develop proposals and produce material another agent can use. Small coding tasks are possible through Bash. The purpose is to make a web conversation a normal participant in Aegis: it has a session identity, working directory, permissions, inbox, transcript and lifecycle, and can be spawned or delegated to like an existing harness.

Alternatives considered

Four independent harness implementations would allow provider-specific behavior everywhere but duplicate execution, recovery and transcript work. The selected approach exposes four selectable harness entries backed by one implementation. The other rejected presentation was a research-specific results column: it adds a second organization for outputs and departs from the current transcript. Future improvements to finding results should serve ordinary sessions too.

A server browser or API-backed agent would change the account, manual interface and authentication behavior that motivates this feature. Neither replaces the selected personal-Chrome path.

03Architecture and integration boundaries

Integrate behind the existing Harness and Process contracts: the shared process wrapper creates a small local driver, reports its PID and conversation resume identifier, and implements start, send, interrupt, terminate, catalog and supported controls. The driver emits a dedicated internal event stream; its parser folds those events into existing user, prose, thinking, tool, system, file and error entries. Do not introduce provider branches throughout Session.

The driver receives the same launch context as other harnesses, including the session-specific MCP credentials through the existing private environment or file mechanism. Bash children inherit that identity so aegis call is authenticated and scoped normally. The provider never receives the token, private credential-file contents or a local process environment dump. A brief is not a security boundary.

Use the existing Chrome grant and operation machinery. One web session owns one provider conversation and one exclusive tab lease. A tab cannot simultaneously be the backing tab of two web sessions. The server validates session ownership before every action; the extension validates the grant and current holder again. The driver uses a private, narrowly scoped transport to operate its own tab; enabling a web harness must not require exposing unrestricted browser tools to the web model or widening its configured tool scope.

The initial adapter contract covers: create a fresh conversation, identify its stable URL or ID, submit a message and recognize its echo, observe ordered messages and final-answer state, extract Markdown and code fences with language and body intact, read available capability metadata, request stop, and recognize login or other human-required states. Attachment upload and generated-artifact enumeration are separate later capabilities. Adapters return observed facts and explicit unsupported or unknown states.

Aegis currently assumes local harnesses in discovery, availability probes and configuration validation. Add four explicit choices backed by this common harness, with browser readiness as their availability condition. Do not add an API-key requirement, invent a CLI binary per provider or perform browser interaction during catalog display.

04Session lifecycle and manual intervention

  1. Spawn. Create the normal session and driver. Ask through the existing extension for a new provider tab. A grant opens the requested conversation; missing Chrome, login, age confirmation or consent puts the session in a visible needs-you state. No queued work silently opens an ungranted tab.
  2. Prime. Send the generated session brief once, associate its acknowledged provider message with the session, then send the user's or delegating agent's task. Record both operations before beginning a command loop.
  3. Run. Observe the final-answer surface, append or update prose, and execute a marked block only after the provider reports that its response has completed. Keep thinking, provider-native research activity and final answers distinct when observable.
  4. Wait or finish. One provider response ending is not a completed Aegis turn if it requested Bash. Execute the block, deliver its result, then continue observing. A final answer without an executable block completes the turn. A turn_end call updates the normal attention card; do not kill the Bash call before collecting its result. Queue workers finish through the existing end-of-turn rules.
  5. Manual control. Use the existing Pause or handover ownership. Stop queued submissions and command dispatch while the person holds the tab. The person can upload files, change modes or converse in the source page. On return, reconcile provider messages and record manual messages as such before draining pending Aegis input.
  6. Disconnect. Retain messages, delivery records and pending local results. Show waiting for Chrome; do not mark an inference failure merely because the extension socket is absent. A revoked grant, closed tab or sign-in requirement surfaces a specific needs-you reason.
  7. Resume. Reattach to the saved conversation ID, validate its provider and reconcile its observed message cursor and delivery records. Reuse the existing conversation; never silently start a fresh one, resend priming or repeat the last command. Reloading or navigating the source tab to a different conversation pauses the session for recovery.
  8. Interrupt or sleep. Freeze new dispatch first, kill a running local Bash process group, and request provider Stop when available. Never resume execution of an interrupted response. Sleep or archive terminates the local driver and releases active control but preserves conversation metadata. Leave the person's Chrome tab open; resuming may request a new grant to that same conversation.

Messages arriving while the provider is generating are queued, as for a harness without mid-turn steering. The first version advertises no mid-turn steering or notice steering. It sends pending notices at safe message boundaries. It does not synthesize a provider cancel operation where none is verified.

05Marked Bash and reliable delivery

A request is a completed Markdown fence whose language is exactly bash and whose first nonblank body line is exactly # aegis: execute. Parse the observed Markdown into blocks and accept only a top-level fenced-code node, outside quotes and lists; do not search rendered text with a global regular expression. Text surrounding it remains prose. Unmarked Bash, other fence languages, quoted examples and incomplete or still-streaming fences never run. The primer asks for at most one executable block per response; multiple marked blocks are refused together with an explanatory tool result rather than partially executed.

```bash
# aegis: execute
# Search the Aegis help
aegis call help_search query="tools from shell" limit=1
```

Run the accepted block as one noninteractive Bash script in the session working directory. Commands may change directory within the block; the next block starts in the configured session directory. Use normal Bash exit semantics; do not silently add shell options that change the authored script. Capture stdout, stderr, final exit code and cancellation separately. A failed command result is still delivered so the model can adapt.

The wire result is ordinary text, not model-authored JSON. Internal structured events and durable records remain appropriate. Preserve output boundaries so a file's text cannot be interpreted as a new command request. Only the provider's final assistant answer can issue an executable block; an echoed result, citation, user message or thinking region cannot.

Execution and recovery records

Identify each execution by session ID, stable provider assistant-message ID and block index. When a provider has no stable message ID, assign one durably to its observed message instance; content hashes alone are insufficient because two legitimate turns can request identical commands. Persist the exact code hash and a prepared record, then persist started before spawning. Store the completed result before requesting delivery to the provider.

The states are prepared, started, completed, delivery-pending and delivered, with interrupted or uncertain outcomes recorded explicitly. A repeated observation of the same block reuses the execution record. If a crash leaves a started command without a durable result, treat it as uncertain and require human resolution; do not promise exactly-once execution or rerun arbitrary Bash. Before delivering a pending result after a disconnect, look for its execution identifier in the observed outbound provider messages. If submission may have succeeded but cannot be confirmed, pause for reconciliation instead of automatically duplicating it.

The result cap is 64 KiB per stream in the provider message. Keep complete output in the normal local tool-output store, report truncation and its retrievable path, and let later tool requests read more. Initial implementation constants are a 120-second foreground command deadline and existing process-group cancellation. Long work uses Aegis's ordinary background, monitor and feed facilities. These limits are implementation proposals, not user-configured preferences already agreed.

06Permissions and honest capability reporting

The current launch contract passes a permission level to each harness; the harness implements its native execution restrictions. The Chrome grant controls tab access, not shell execution. Aegis's host policy and MCP tool scopes continue to govern every aegis call, but those checks do not constrain arbitrary Bash subprocesses.

For the first implementation, conservatively classify every free-form Bash fence as execution. At read or write, decline it and send a tool refusal explaining the permission limitation. Web-native conversation and research can continue; the initial Bash-only interface provides no local file-editing path in write mode. At auto and full, allow execution only after launch policy accepts the selected level, under the driver's normal launch identity and process tree. Never silently promote a restrictive session to full.

Implementation proposal for review: this conservative mapping preserves the existing execute boundary, but does not provide read-only shell tools. Supporting arbitrary read-only Bash, path or network isolation, or selective approvals is separate work. Do not describe the bridge as a shell sandbox or claim restrictions supplied only by priming.

Recheck the current session permission before starting a prepared command. Reducing permissions while a command is already running stops that process before another block can dispatch. The bridge does not advertise configuration guarantees it cannot meet: harness_tools: false disables free-form Bash, and an isolated-harness request is refused unless an actual supported launch mode satisfies it. Extra MCP servers are not automatically available through aegis call; the first version supports Aegis's registered operations, and reports other transports unsupported.

A provider's own web tools and the person's account entitlements remain outside local Bash permissions. A local read-only setting does not imply that the provider cannot browse, generate media or perform actions through its own web interface. The host decides whether that provider is suitable for the requested agent.

07Priming and normal agent behavior

Generate the brief from the same session and host inputs as ordinary harnesses: role and task context, identity, working directory, permission, configured priming, applicable workspace or project instructions, Aegis operation discovery and the usual knowledge rules. Add the small Bash bridge contract. Do not duplicate the entire tool catalog or the browser's chat history in every prompt. Read applicable local instructions server-side before sending them; a web model cannot discover those files without an execution request.

Web chat does not provide an API system role. The prime is a visible initial user message, and browser tools or provider instructions may outrank it. Record that limitation instead of presenting it as an enforced system prompt. Persist the brief version, hash and acknowledged provider message ID. A model acknowledgement is not evidence that permissions are enforced.

Priming readiness is a distinct state: do not run executable content produced in response to the primer alone. The first actual task activates the execution loop. New sessions receive the prime once; resume reconciles it. A changed working directory, role or permission is conveyed as a clearly identified session update at the next safe boundary. Regeneration, edit-and-resend and conversation branching in the provider UI require reconciliation before executing any affected response.

08The current transcript, with a Chrome connection

Keep the existing transcript's rows, thread, tool details, fold levels, read marks, navigation, file cards, composer and controls. A marked code block becomes the arguments of one ordinary Bash tool entry; do not also render a second executable request card. Preserve its original provider text and message identity in the internal record. Prose before and after the block remains ordinary agent prose.

The only proposed addition in this view is a quiet connection row with an action that opens or focuses the backing Chrome tab. Pausing and returning control use the existing Chrome ownership semantics. Reuse the established needs-you and waiting states for login, manual work and disconnection. Do not create a separate research dashboard or mirror the provider page inside Aegis.

09Adapter compatibility

Each adapter declares supported URLs, how to create and identify a conversation, verified input and submit actions, message identity, final-answer boundaries, native completion and cancellation signals, and detectable login or intervention states. Support initially covers the standard text-chat mode actually verified on each provider. Deep-research and media-generation modes are capability additions with their own completion and artifact tests.

The adapter observes the page through the extension's existing authorized transport. Prefer a DOM observation subscription for changes; a bounded timer-based snapshot loop is acceptable until observation is available. Never make an Aegis reasoning agent repeatedly inspect screenshots to keep the harness running. Keep observation within the granted conversation and stop subscriptions when its lease ends.

A missing Stop button by itself is not a verified completion signal. A supported mode must combine its message and explicit completion or settled-action state, verify that the final-answer content is complete, and distinguish waiting for a person. An unknown layout, ambiguous branch, incomplete extraction or unsupported mode pauses with a clear reason before any Bash runs. Preserve a sanitized diagnostic snapshot for adapter repair; do not silently submit again.

Manual uploads can take place in Chrome from the start. Record their observable attachment metadata when available without pretending that the bridge received file bytes. A person changing the selected model or mode is authoritative; the next adapter observation refreshes metadata and capability checks.

10Files and generated artifacts

In the first version, local Bash-produced files can be shared through the existing Aegis file operations, and those operations produce the current transcript cards. A provider-web image, document or download becomes a local Aegis artifact only after an explicit capture succeeds. A link or visible thumbnail is not a captured file.

Later adapter capabilities enumerate artifacts by provider conversation, source message and artifact identity, fetch or download bytes through the authorized browser, and transfer them to the session's file store. Record filename, MIME type, size, checksum and origin. Apply the existing file limits and preview rules, and use the ordinary file card, viewer and docking behavior. Failure to capture retains a source link and an actionable error instead of an empty local file.

Generated images, including image-generation features accessed through Gemini, are an explicit target of this extension. Provider-specific controls and download behavior must be measured before specifying their implementation. Automatic server-to-provider uploads, rich research reports, generated audio or video, and an Aegis model or mode selector are later capabilities, not prerequisites for the first text-and-Bash release.

11Scope, delivery and builder choices

This is a project rather than a small adapter patch: it adds a harness driver, a Bash execution boundary, durable browser-command delivery and four independently changing provider integrations. This design does not authorize product implementation or change the repository's milestone priority. It needs maintainer approval before an implementation plan.

  1. First complete slice. Implement the common harness and one adapter with a fresh tab, normal transcript, priming, marked Bash, session-specific tools, manual control, stop, reconnect and uncertain-execution recovery. This slice must stand alone as a usable delegated research agent.
  2. Four-provider acceptance. Add the remaining adapters against the same contract, run the same real bridge tests and expose each as a selectable normal harness. The first complete feature supports all four; do not claim four from the prototype alone.
  3. Progressive capabilities. Add verified artifact capture and richer modes without changing the core session or Bash protocol.

The builder chooses internal module names, event serialization, observer implementation, the first adapter to land, storage mechanics consistent with existing session persistence, and fixture organization. The semantic contracts in this document are fixed unless the implementation plan explicitly proposes a change. New tests and commands that can be mechanical checks belong in the repository's executable checks rather than being copied into agent instructions.

Non-goals: adopting existing chats at initial spawn; a new OAuth or API-key flow; a provider iframe or video mirror in the transcript; guaranteed remote inference while Chrome is offline; a new general shell sandbox; hiding or bypassing provider login, human-verification or account limits; and inferring unavailable cost or usage metrics.

12Acceptance, failure cases and approval

  • For each of the four providers, spawn a fresh session in the person's granted Chrome, deliver the prime once and complete a marked Bash → real aegis call help_search → result → final-answer exchange.
  • A second agent can delegate a real research task and obtain the final answer through existing session operations. A configured queue using the web harness finishes and returns its result through the ordinary callback path.
  • Unmarked examples, thinking text, multiple marked blocks, incomplete fences, streaming content and echoed tool output do not execute. Break the marker and completion detector deliberately to confirm these checks fail safely.
  • A web session's aegis call uses its own identity and tool scope. The provider conversation and transcript contain no credential. Restrictive permissions refuse Bash; a change of permission cannot widen a pending execution.
  • Reload the source tab, disconnect Chrome before and after result delivery, restart the driver around command start, and replay the same observed message. Known executions are not repeated; an uncertain execution or delivery waits for human resolution.
  • Pause for a manual upload or model change and return control. No agent input is submitted while the person owns the tab; their messages are reconciled without duplication.
  • Interrupt stops the local process group and prevents commands in a late provider response from running. Sleep and resume preserve the conversation association without closing the person's tab or replaying priming.
  • The native transcript, tool expansion, folding, read marks and composer remain usable at desktop and 390 px. No unobserved cost, progress or provider-native tool activity is shown as measured.
  • Provider fixtures cover the final-answer and completion surfaces actually observed in live tests. A layout mismatch stops execution and shows its reason. Static fixtures supplement, rather than replace, a live trial for each supported provider mode.
  • Generated-artifact acceptance is separate: capture original bytes, verify their checksum and open the actual saved file through the existing Aegis viewer.
