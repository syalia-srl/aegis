Claude Code on another account: the pool a session draws on, and a connection per agent

docs/superpowers/specs/2026-11-21-claude-code-on-another-account-design.html·proposed, not started·written against main a2c8d5e

Claude Code already talks to OpenCode Go's Anthropic endpoint, with no adapter. aegis can start it there, but it then counts the session against the wrong account. The Fleet shows Claude's gauge for it, it gets Claude's quota notices, a Go limit cools every Claude model, and the turn is billed to the Claude subscription at Opus prices. This spec makes the pool a property of the session, not of its harness. It also gives a claude-code agent a connection of its own: an endpoint, a key and a pool. No new harness is added.

01What this delivers

A · The pool a session draws on

One function answers which account a session spends: its recorded pool when it has one, else what its harness and model imply, as today. The five places that ask pool_for today ask it instead. The session card carries the pool, so the browser stops deriving it. Cooling, Claude's stream readings and the Claude sign-in card apply only to sessions whose pool is claude.

B · A connection per agent

A claude-code agent may name base_url, pool, an optional api_key_file and a restricted env:. aegis starts Claude Code against that endpoint and keeps the Claude sign-in token out of its environment; an isolated session also does not link the person's credentials file, and one that is not isolated keeps the person's ~/.claude, which aegis doctor warns about. The switch is the agent's, never forced. With pool: opencode-go the key comes from where the Go gauge already reads it, so there is never a second copy.

Cost that says what it knows

A session with a connection drops Claude Code's own total_cost_usd, which prices every model as Opus. Its turns are counted as tokens, unpriced, and billed to the pool's account. aegis doctor checks the connection without spending, and an opt-in probe spends one Claude Code call to prove it works.

03What aegis does today with such a session

Read on main a2c8d5e. Every item is a session whose harness is claude-code and whose process talks to Go:

  • The wrong gauge. The sidebar picks the gauge with providerFor (client/js/gauges.js:249, its only caller client/js/parts/sidebar.js:854). That function matches on the harness, so the session shows Claude's gauge.
  • The wrong guard. App reads the pool of a start from pool_for(spec.harness, model or spec.model) (app.py:1079) and passes it to guards.levels (app.py:1081). So an agent's quota: {opencode-go: …} guard never holds this session. A claude line would hold it, although the session spends nothing of Claude. The starters' levels make the same mistake (guards.py:172).
  • The wrong notices. notices.py:813 picks the quota:<pool> notices a session receives. This one is told that Claude is on pace for its limit and asked to spend less.
  • The wrong cooling. If Go's limit error matches the Claude patterns (usage limit|weekly limit|hit your limit|\d-hour limit, cascade.py:87-91), the fall is scoped to the pool. Pools are keyed by harness, and _pool answers claude for every claude-code model (cascade.py:115-118, :128-147). A Go limit would therefore cool the real Opus sessions. Whether Go's text matches is not measured.
  • The wrong schedule line. schedules.py:304 reads a fire's line on pool_for(harness, model).
  • The wrong bill. _billing (usage/turns.py:742-753) bills the Claude subscription unless apiKeySource names a key; it was "none" (measurement 7). _close takes Claude Code's running total as the turn's billed cost (usage/turns.py:633-640, :657-658). So the turn is billed to Claude at about 27 times its real cost. The same figure feeds a usd budget (#1068), which therefore trips about 27 times early.
  • The Claude token leaks. Every Claude Code process gets CLAUDE_CODE_OAUTH_TOKEN from login.with_token (claude/harness.py:93, claude/login.py:102). An isolated session also links the person's .credentials.json (claude/harness.py:39-48). Every tool child inherits that environment, so a model served by another company would have the year-long Claude token one env away.
  • The wrong sign-in card. A turn that fails to sign in (Result.auth_failed, claude/stream.py:175, :382) makes session.py:1577 call SignIns.failed (signin/core.py:105, :132). That opens the Claude sign-in card. A rejected Go key would ask the person for a Claude token, which fixes nothing.
  • Possibly the Claude gauge itself. A Claude session's rate_limit_event feeds Claude's gauge through Quota.observe, and the end of each Claude turn triggers an early Claude reading (Quota.turn_ended, both in quota/__init__.py). Whether Claude Code emits that event against Go is not measured. The nudge happens either way.

Not a new harness (#943)

#943 records the test the maintainer applies to a proposed harness: "does it reach a model pool or subscription that OpenCode cannot already use?", and closes with "Recorded as a decision; reopen if one of them gains a model pool OpenCode cannot reach." This spec adds no harness, so that test does not come up. OpenCode does reach the Go account. The question here is different: when an existing harness spends an account, aegis should count it against that account.

Not waiting on #457

#457 proposes a lovelaice harness, with agent keys base_url (required), api_key_file (optional, "read at spawn, never inline") and "a quota pool of its own, lovelaice". This spec uses the same names on claude-code, with the same rule for the key. It needs nothing from #457. Slice A is what #457's own pool would need anyway: a pool that is not derived from the harness.

06A. The pool a session draws on

One resolver

# quota_gate.py, beside pool_for (:82), which stays as the derivation
NONE = "none"   # a pool a session names when aegis reads no gauge for its account

def pool_of(spec: SpawnSpec, model: str | None = None) -> str | None:
    """The account a session draws on: the pool its spawn recorded, else
    what its harness and model imply (pool_for). ``model`` asks for another
    model of the same session, as a cascade's pick does."""

def pool_of_record(rec: Mapping) -> str | None:
    """The same for a spawn record or a meta, as guards.levels reads a starter."""

# cascade.py, where cool writes and until and pick read: one key, one function
def cooling_owner(harness: str, base_url: str | None) -> str:
    """The owner a model fall is keyed by: a connection's endpoint, else the
    harness, so two gateways never share one and an endpoint id never
    collides with a harness's."""

A recorded pool wins, and "none" answers None, which decide already reads as an account with no gauge. With no recorded pool, the answer is pool_for(harness, model), the same as today. Every existing record and every agent without a connection therefore keeps its pool. pool_for keeps its tests (tests/test_quota_gate.py:38-41).

What only Claude's pool does

  • Quota.observe takes a session's rate_limit_event only when pool_of(s.spec) == "claude". The test belongs where the session reports it, in Host.rate_limit (registry.py:576, declared at session.py:241).
  • Quota.turn_ended nudges the Claude reading only after a turn whose pool is claude. It stays routed by harness (registry.py:262 passes spec.harness), and OpenCode was never nudged (quota/__init__.py:297-310). A Go session therefore refreshes nothing after its turn, and a quota: guard on that pool reads a reading up to one poll old. That is today's behaviour for OpenCode and stays a non-goal.
  • At session.py:1577, SignIns.failed (signin/core.py:132) is called only when the session's pool is claude. Any other auth_failed stays an ordinary failed turn, whose error text names the endpoint.

With no connection anywhere in the file, all three behave exactly as now. That is the claim slice A's tests must hold.

An agent's nested provider: map is merged into the agent before it is read (agents.py:129-135), so the four keys are validated there too, and a connection written inside provider: is refused: that map names models, not an account.

Spawn, overrides and the record

  • agents.resolve (agents.py:273, the spec built at :311) copies the agent's connection and pool into the spec. If the spawn overrides harness, both are dropped and the pool is derived again. If it overrides model, both are kept. A cascade's models all run on the agent's connection.
  • SpawnSpec (session.py:263) gains pool: str | None = None and connection: Connection | None = None, where Connection is base_url, api_key_file (a path, or None for the pool's own key) and env. record() (:324) writes them only when set, and from_record (:366) reads them, so an old record loads as today. The record holds the path of the key file, never the key.
  • A resume reads the connection from the record, never from .aegis.yaml, as for everything else in the spec. Editing the agent does not move old sessions to a new endpoint.
  • The key is read when each process starts, like the Claude token. If OpenCode rotates its key in opencode.db, the next start or resume uses the new one.

The process environment

Launch (harness.py, built at session.py:929) carries the connection to the harness. Starting from session_env (harness.py:128), ClaudeSession (claude/harness.py:66-93) then does the following for a connection:

  1. removes CLAUDE_CODE_OAUTH_TOKEN, ANTHROPIC_API_KEY, ANTHROPIC_AUTH_TOKEN and ANTHROPIC_BASE_URL from what it inherits;
  2. adds ANTHROPIC_BASE_URL, ANTHROPIC_AUTH_TOKEN (the key) and the agent's env;
  3. does not call login.with_token (:93);
  4. for an isolated session, does not make isolated_env's link to .credentials.json (:39-48). Isolation removes the link, not the reach: HOME is left alone, so a tool child can still read ~/.claude/.credentials.json, as it can in any Claude Code session on this machine. Only a sandbox would close that, and this spec adds none.

The recap and /btw one-shot calls of a connection agent get the same environment (oneshot.py). The composer's catalog probe (ClaudeCode.probe, claude/harness.py:153) would list Anthropic's models, so for a connection session /model offers the agent's own models (agents.model_suggestions, agents.py:259).

The header: the gateway requires a session id, and Claude Code sends x-claude-code-session-id on every request (measurement 2). aegis neither sets it nor exposes it. The module docstring and the help page say that the endpoint depends on it, and the probe and smoke test below fail with 400 MissingSessionID if a Claude Code release stops sending it.

08Cost

Today, _close (usage/turns.py:624) takes Claude Code's running total from each result as the turn's cost, with cost_kind billed (:633-640, :657-658). Without a total it prices the turn's tokens (_rates, :611-616, Anthropic's table for claude-code), and else counts them unpriced. A bare Go id has no price (usage/prices.py:12-14; tests/usage/test_prices.py:27 for an OpenCode id).

The deriver is not the only path from a result to a cost. The session's own cost_usd is set from the stream result's total_cost_usd (session.py:1597, from claude/stream.py:367-375) and leaves on the card (session.py:642); the API diffs it per turn (api/sessions.py:152, :245-253). And usage/scan.py prices a stored message again by harness, forcing claude-code to Anthropic's table and its default model when there is no init line (:113, :319-321). A connection has to reach all three, or the card and a replayed transcript keep Claude's figure while the usage tables are right.

With a connection in the spawn record:

  • the result's total is ignored: neither billed nor _prev_total moves;
  • _rates answers None, because the endpoint's prices are not Anthropic's, even for a model with a Claude-like id;
  • the turn is unpriced, with every token counted;
  • the card's and the API's cost_usd are dropped with it (session.py:1597, :642, api/sessions.py:152), so a connection session shows tokens and no dollars;
  • billing is the pool's account (opencode-go:<account>), or api for pool: none.

Consequences:

  • The subscription split credits rises of the Go weekly window to these turns, not to Claude.
  • A usd budget (#1068) counts nothing for such an agent, so its caps must be tokens, and doctor warns about a usd-only budget on it.
  • Pricing from the gateway's usage.opencode.list_cost is left out. Whether stream-json even keeps that field is not measured.

09doctor and the probe

doctor._agent (doctor.py:281) reports for an agent with a connection:

  • no comparison with Claude Code's catalog;
  • ok: claude-code deepseek-v4.1-flash at opencode.ai, pool opencode-go;
  • error: no key (a file problem, or the pool's reader returns nothing);
  • warn: pool: none ("no gauge meters this agent's spend");
  • warn: a connection agent that does not set isolated, whose tool children can read the person's ~/.claude and .credentials.json; the switch stays the agent's.
  • warn: a usd-only budget;
  • warn: a quota: guard that names a pool other than the agent's own, which never holds its sessions.

The doctor spends nothing and writes nothing (doctor.py:1-12), so the probe is opt-in, for example aegis doctor --probe go-claude. It runs Claude Code itself, in the shape of login.probe (claude/login.py:141):

  • a scratch CLAUDE_CONFIG_DIR;
  • claude -p --model <model> --output-format json --tools "" --setting-sources "";
  • the agent's connection environment, built as in section 07;
  • Reply with the word ok. on stdin.

Claude Code supplies its own user agent and session header, so the probe meets neither Cloudflare's 1010 nor MissingSessionID. No aegis HTTP client borrows a user agent. The probe costs one call on the agent's account; its input-token size with no tools is not measured.

12On this server, merged or not

The server that measured this runs 2.22.0 from PyPI (uv tool install aegis-harness). Main is 349 commits ahead, and the guards and budgets this spec extends exist only there. These patches therefore apply to main or to a release cut from it, not to 2.22.0.

  • Until then: the wrapper. ~/bin/claude-go-router gives the wire and the account today, with no change to aegis. Everything in section 03 still applies to it: wrong gauge, wrong notices, wrong bill, the Claude token in the environment unless the wrapper unsets it, and possible cooling of Opus.
  • If the PRs are not merged: a branch of one's own, rebased onto each release tag and installed from a local clone. This beats .patch files on the installed package, which fail silently. A rebase stops at each conflict, and the tests run against the new release.

13Non-goals and open questions

Non-goals

  • No new harness, and no protocol translation or proxy: Claude Code speaks this door natively.
  • No two accounts of one provider: PROVIDERS stays one instance per provider (quota/__init__.py:53). A pool as an account name does not rule it out later.
  • No connections for other people's sessions. Open-source aegis is one person's server (AGENTS.md, #957), so there is no member with a key of their own.
  • No Go free models: they answer 403 outside OpenCode.
  • No price for Go turns: they stay unpriced, not priced as something else.
  • No pool: on Pi or OpenCode in this spec, although Pi already reaches Go (section 04).

Open questions for the maintainer

  1. Should base_url require pool:, including an explicit none, as proposed? Or should a missing pool read as none?
  2. answered Should a connection session always run isolated, with its own CLAUDE_CONFIG_DIR, even when the agent does not set isolated? No. The switch stays the agent's own, false by default (agents.py:88): a connection agent that leaves it off keeps the person's CLAUDE.md, skills and MCP servers, and aegis doctor warns that its tools can read ~/.claude/.credentials.json. Forcing it would not close that anyway: HOME is unchanged, so the path stays readable; only a sandbox would close it.
  3. Should env: values take ${VAR} from aegis's environment, as mcp: does (mcp_servers.py:5-10), so that a credential may travel by reference instead of being refused by name?
  4. Should pool: also be allowed without a connection, for Pi on opencode-go/… models, which pool_for answers None for today, and for OpenCode providers with no prefix match?
  5. Should the probe be aegis doctor --probe <agent>, a button on the agent's Settings row, or both?
  6. answered Does anything in the client read the Cooling wire's harness field, which a pool fall would replace with the pool? Nothing does: Cooling.wire has no caller in main a2c8d5e. A pool fall names the pool in it anyway, so a later reader is not misled.
  7. Should a usd-only budget on an unpriced agent be a warning, as proposed, or an error?
  8. Later: price Go turns from the gateway's list_cost, if stream-json keeps it?
