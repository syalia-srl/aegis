Repository gc with explicit approval

Status: implemented. Local scanner, MCP, browser, static and real Codex validation passed; PR validation follows. Issue #1127.

Goal

Provide reusable evidence for cleaning inactive repositories while requiring the person to select and approve every deletion plan.

Flow

  1. The CLI, /gc and gc_propose call a read-only scanner. It discovers Git repositories under an explicit root, recognizes build artifacts from project manifests and markers, and explains exclusions.
  2. A transcript card records the complete inventory and immutable metadata snapshot. The card shows activity dates, allocated bytes, a hard-link-aware conservative estimate and rebuild instructions. Its controls work at desktop and phone widths.
  3. The user selects candidates and clicks approval. gc.decide is user-only and absent from MCP. Cancellation deletes nothing. The terminal CLI requires an interactive selection and confirmation.
  4. The proposal is marked running before any await, so another browser or restart cannot replay approval. Execution rescans current source and artifact state, tracking, ignore rules, process references, launchers and active session directories; only unchanged selected candidates can be removed. Changed candidates are skipped.
  5. The same card records removed and skipped paths, errors, actual free space and tracked-file-state verification, then wakes the proposing session.

Boundaries

No shared-cache cleanup, source deletion, build execution, automatic approval, or extension of existing archived-session gc. Unknown directories and inspection failures are kept. Process inspection requires Linux /proc. Advisory metadata checks reduce races; fd-based deletion refuses symlinked parents and a replaced artifact root. Full-permission agents still have their ordinary shell access; this approval guarantee applies to aegis operations.

Validation

Core scanner and executor tests cover stale artifacts, recent writes, tracked files, unclassified data, process and launcher references, active worktrees, hard links and changed identities. Real MCP tests cover proposal/read, forbidden agent approval, fixed selection, cancellation, replay and restart. Browser tests exercise both entry points, selection, approval, cancellation and phone layout against a newly started server. Existing gc and documentation tests protect compatibility.
