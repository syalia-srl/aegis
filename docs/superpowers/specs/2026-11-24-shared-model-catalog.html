Shared model catalogue

Status: implemented. Issue #1130.

Problem

The existing nightly ranking depends on harness models visible to a CI runner. Its 2026-11-23 snapshot contains 40 IDs and only 24 Intelligence Index scores. It cannot describe public provider offers or free status.

Data and publication

The existing public model-ranking branch carries one models.json snapshot. Artificial Analysis scores refresh daily. All models.dev provider offers refresh hourly, excluding deprecated or discontinued entries. Provider token prices and benchmark list prices are separate. Unknown token prices give unknown free status. Every benchmark slug is retained; exact normalized IDs, canonical IDs and labels map advertised offers to scores. Unmatched offers remain unranked.

Instances and queries

Instances fetch every 15 minutes. Atomic replacement follows schema validation and rejects older benchmark or offer versions. Failed refreshes preserve the last good snapshot; packaged data remains the offline fallback. The existing model_ranking switch disables requests.

models.catalog is a read-only paginated operation, exposed as models_catalog. It filters provider and free status and returns independent benchmark and offer timestamps. Rank orders unique benchmark models, so different providers of the same model share a rank. This catalogue describes advertised offers, without granting credentials, quota or permission. models.list continues to describe local harness models.

Verification

Regression coverage exercises catalogue parsing, unknown and zero prices, score mapping, hourly refresh without a benchmark API call, rejected empty refreshes, timestamp rollback, filtering and pagination. Browser checks exercise the existing model list against a newly started server. Public-source retrieval exercises the actual hourly script.
