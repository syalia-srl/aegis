System One decisions for aegis

Research and a spike on Jev 1.14 through OpenRouter · 2026-11-16 · names of people, machines and clients in the cases are replaced · 166 live requests, $0.0058 spent

Executive summary

A System One model answers typed questions about a piece of text (pick one option, yes or no, a score) with a probability, and writes nothing else. TypeSafe's Jev is the first; OpenRouter serves it at an undocumented alpha endpoint, /api/alpha/decisions, at $0.042 per million input tokens and free output.[1][2] In this spike every request took 0.4 s at the median and cost between $0.013 and $0.11 per thousand calls.

Six decisions in aegis fit this model, and the spike supports four of them right away:

  1. A real "auto" level for OpenCode, Cursor and Codex sessions. Today aegis's auto on those harnesses is a fixed table that lets every shell command run; only Claude Code has a model behind auto. With a confidence floor of 0.85, a Jev gate ran 10 of 16 routine commands without asking and 0 of the 24 risky ones. It cannot block on its own: it was confident (0.8 or more) about only 2 of 16 commands that deserve a block, so everything uncertain goes to the person, as it does now.
  2. Picking the know-how for a task. Across a real library of 35 know-how docs the right one ranked first in 11 of 12 tasks, and the two plain questions got no doc. Today aegis lists every repo doc at once.
  3. The card when an agent forgets turn_end: 14 of 15 right, and the miss had low confidence (0.44), so a threshold sends it to today's nudge.
  4. A yes/no workflow judge on inputs that are already in the workflow: 11 of 12.
  5. Waking on a feed item (9 of 10) and spotting injected instructions in tool output (8 of 8) also work, on smaller sets.
  6. Queue routing (10 of 10) and error fall/stay (10 of 10) scored perfectly, but the routing labels are my own opinion and the error rules in cascade.py already work, so both are low value.

None of the work Orca or T3 Code automates is a decision: they use models to write titles, branch names, commit messages and PR text, and they read agent status from hooks.[5][6] The System One work is in the community around Jev: about sixty projects route models and skills, and about seventy gate tool calls.[7] The closest thing to item 1 is Claude Code's own auto mode, which runs Sonnet in two stages and publishes its error rates.[3]

Recommendation: aegis calls no model and holds no key (#715), so the decider cannot live in the core. Build it as a plugin (#718) that the host turns on with its own key, with the core behaving exactly as today when it is off. Ship items 2 and 3 first, which are cheap and safe because a wrong answer only costs a nudge or an extra doc. Item 1 is the biggest change in what aegis can do, and it needs a bigger labelled set from real transcripts before it guards anything.

1. What a System One model is, and how aegis would call it

A request carries a state (any text up to 32k tokens) and named questions of three types: choice (one of up to 255 described options, returned with a confidence), noul (probability of yes) and score (a place on an ordered rubric). The answer is JSON with no prose and no reason.[1][2] Jev's weights are closed. Open models of the same class exist (decider-4b, Von, pplx-decider, FLock's THIS/THAT), and decider-4b's server accepts TypeSafe's request shape, so a local GPU machine could later serve the same API.[8] I did not test any of them.

POST https://openrouter.ai/api/alpha/decisions
{"model": "typesafe/jev-1.14", "state": "...", "questions": {"verdict": {"type": "choice", "instructions": "...", "criteria": {"allow": "...", "ask": "...", "block": "..."}}, "secret": {"type": "noul", "instructions": "..."}}}

The endpoint is not in OpenRouter's public model list, which only shows Jev Router, a model picker that runs on Jev.[2] Every request in this spike went through it.

Where a decider sits in aegis

The vision issue says aegis calls no model and holds no key: every model call is made by an agent the person configured, as recap and /btw run through a configured agent. A direct HTTP call to OpenRouter would break that. Three ways keep it:

  • A plugin (#718) that registers a decider; the host enables it and holds its key. Off by default, and every use falls back to today's behaviour when it is off or fails. This is the one I recommend.
  • The host policy (#957): the gate in 4.1 is a decision about which tool calls an agent may make, which is exactly what the host policy decides. An embedding host could put Jev behind its policy without aegis knowing.
  • A local model served on the same API (decider-4b or similar), which keeps the text on the person's machines but needs a GPU and its own evaluation.

2. What other harnesses decide

Orca and T3 Code

Both are meta harnesses like aegis: they run Claude Code, Codex, OpenCode and others in worktrees. I read their source trees. T3 Code's model calls are all text: generateCommitMessage, generatePrContent, generateBranchName, generateThreadTitle, generateReviewGuide and transcription cleanup.[6] Orca's are chat naming, worktree branch names and commit messages; its agent status and "needs attention" come from agent hooks and terminal signals, not from a model.[5] Neither makes a typed decision with a model, so neither has anything a System One model would replace. aegis already does more here: recap, /btw and group names are its text calls, and the decisions below are ones neither tool makes.

Claude Code auto mode

Anthropic's own classifier is the reference for item 1. It runs Sonnet 4.6 in two stages: a single-token filter told to err towards blocking, then chain-of-thought only on what the filter flagged. It reads the user's messages and the tool calls but not the agent's prose or the tool outputs, so the agent cannot argue its way past it. On 10,000 real actions the filter alone stopped 8.5% of harmless ones and both stages 0.4%; on 52 real overeager actions both stages missed 17%.[3] aegis's auto on Claude Code maps to this mode (src/aegis/claude/process.py:37).

Jev in coding agents

The awesome-jev-tools list names well over a hundred projects.[7] By count: model, effort and skill routers for Claude Code, Codex, Pi and OpenCode (about sixty); tool-call gates and guardrails (about seventy, such as jev-guard, pi-verdict, open-jev-approvals, the fx agent's built-in reviewer); review and CI gates (DiffJury, jev-commit, JevGate); context pruning and reranking (fast-jev-compaction, Oko); and loop control such as Foreman (is a Codex worker's output complete or does it need a person) and limpet (a Stop hook that checks completion rules). Two designs matter for aegis:

  • omp-jevens-classifier sends the command, the working directory and the last three user messages, asks one verdict choice plus nine hazard questions and a blast-radius score in one request, and maps the answers to run, ask or block with tunable thresholds. Every failure (timeout, bad answer, no key) fails closed into a prompt. It reports about 0.6 s and 528 input tokens per request.[4]
  • Octomind keeps Jev reasoning-blind like Anthropic's classifier and measured what a planted sentence does: one line claiming pre-approval moved p(block) on rm -rf ~/.ssh from 0.76 to 0.48 and confidence from 0.64 to 0.22. Its runs cost about 415 tokens and 386–834 ms per call.[9]

Today

At 0.85 nothing risky ran, and at no floor did the gate block a routine command. Injection
A comment claiming approval did not turn any verdict into allow. On rm -rf ~/.local/share/aegis it turned a block at 0.64 into an ask at 0.11, the same effect Octomind measured: the planted text buys doubt, not permission.[9] Strip comments before sending.
Hazards
The hazard questions fire on harmless pushes and deploys ("shared state" at 0.96 for pushing a feature branch), so they work as reasons shown to the person, not as a veto.
Latency, cost

Next
Label 300–500 real commands from DeepSeek worker transcripts, pick the threshold from those, keep the fixed allow rules in front (reads, tests, git in the worktree), and fail closed to ask on any error or timeout.

4.2 Pick the know-how and skills for a taskbuild

Today
When a session enters a repo, aegis sends every know-how doc with "read those that match"; this session got all five aegis docs for a research task that needed none. The send-time hint ranks skills and memories with BM25 and vectors (src/aegis/knowledge/hint.py).
Decision
Which docs this task needs, if any.
Result
With one yes/no per doc (35 in one request), the right doc ranked first in 11 of 12 tasks and was in the top three in 11; the two plain questions put no doc above 0.4. The miss was the release task: aegis-delivery-flow scored above 0.4, but landing-a-change, keeping-a-vision-issue and project-docs ranked higher, and nine docs passed 0.4. A single choice among 36 was worse (12 of 14), so use one yes/no per doc and send the top two or three above 0.4.
Latency, cost
0.43 s and $0.11 per thousand tasks with 35 docs. Run it on the first message and on a cwd change, off the send path.

4.4 A decide probe for workflowsbuild

Today
Every judge is a quiet agent session (src/aegis/workflows.py:2532), which costs a session and minutes for a check whose answer is already in its inputs.
Result
11 of 12: it read test logs, a PR body's issue link, voseo against tú, a systemd log and conventional commits correctly. It passed (0.85) a report that cites one source for one price but gives none for the second, a check that needs counting. With the wording "skipped tests are fine" it now passes "214 passed, 3 skipped", which it failed in the first probe without that wording.
Shape
A new probe kind beside judge, with a threshold; below it the step falls back to the agent judge. It loses the why sentence, so the card should show the question and the probability instead.

4.5 Feed filter and injection scanoptional

For a feed on new aegis issues and comments, it said wake for 9 of 10, dropping bot bumps, thanks and "+1". It missed the one that mattered most: a CI failure posted by github-actions[bot] (p 0.30), because the goal text told it to ignore bots. Write the feed goal carefully, or keep a rule for CI. It found injected instructions in 8 of 8 tool outputs (HTML comments, a README, an issue body, a commit message), with no false alarms on 4 clean ones. A warning to the agent from that check is cheap at $0.014 per thousand, but scanning every tool output adds 0.4 s to each.

4.6 Queue routing and error fall/stayskip for now

Routing a brief to opus, deepseek or haiku got 10 of 10, but the labels are my opinion, and an automatic choice would work against the quota rules people set per queue. Error fall/stay got 10 of 10, but the regex rules in src/aegis/cascade.py:99 already handle the known errors; Jev would only help as a fallback for error texts no rule matches.

4.7 Not a fitno

Recap, /btw, group names, and the commit messages, branch names and PR text that Orca and T3 Code generate all need written text.

5. Risks

  • Alpha endpoint. /api/alpha/decisions is undocumented and may change or disappear. Keep the client small, pin jev-1.14, and make every use fall back to today's behaviour on any error.
  • Privacy. Commands, tasks and messages would go to TypeSafe through OpenRouter, a provider the person did not pick for their agents. The gate must never send environment values, and the person should be able to turn the decider off per server.
  • Soft probabilities. Confidence is useful for ordering and for a fallback threshold, but a 0.49 on the right doc and a 0.96 "shared state" on a harmless push show the numbers are not calibrated probabilities. Every threshold above needs tuning on real data.
  • Small, self-labelled sets. 136 cases labelled by the person who wrote the questions. Treat the scores as direction, not rates.
